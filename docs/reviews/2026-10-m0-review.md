# M0 Review — October 2026

Scope: milestone M0 (issues #11–#24) at commit `9229a6d`: `backend/`, `frontend/`, `e2e/`, `deploy/`, `.github/` and the root configuration (`docs/product` excluded). Reviewer stance: bugs and fragile code, security, CI correctness, developer experience, over-engineering, readiness for M1. Severity: **high** = secret/data leak or broken required flow; **med** = likely bug, supply-chain or CI gap; **low** = robustness, noise, consistency.

Method: read all files against the specs ([overview](../architecture/overview.md), [workflow](../development/workflow.md), [coolify](../deployment/coolify.md), [roadmap](../roadmap.md) M0/M1); followed the README quickstart from scratch (dev compose, `dotnet run` api + worker, Vite dev proxy, frontend checks, both Playwright projects); built the three images and ran the production-like compose stack (`--wait`, all healthy, fullstack e2e green); exercised the Caddy log redaction against a dead upstream; ran `coolify-deploy.sh` against a fake Coolify API.

## 2. Readiness for M1

No blockers. Things the M1 issues should account for:

- **Forwarded headers (#28, #30).** The api sees plain HTTP from Caddy. Before `__Host-` cookies (require `Secure`) and per-IP rate limits, add `UseForwardedHeaders` trusting only the `web` network (`X-Forwarded-Proto`/`-For`; Caddy already forwards Traefik's values via `trusted_proxies private_ranges`), and set the cookie `SecurePolicy = Always`.
- **Identity placement (#28).** `ArchitectureRules.ForbiddenForCore/Application` forbid the `Microsoft.AspNetCore` namespace prefix, which includes `Microsoft.AspNetCore.Identity` (`IdentityUser`). Keep the Identity user/store in Infrastructure and expose ports to Application, or consciously relax the rule for Application; don't derive domain types from `IdentityUser`.
- **Data protection keys (#28).** Containers run `read_only` with no volume; without `PersistKeysToDbContext` the key ring is ephemeral per container and cookies break on every restart/replica. Planned per coolify.md §4 — must land with cookie auth.
- **Problem details (#25).** Register `AddProblemDetails()` + `UseExceptionHandler()`/`UseStatusCodePages()` in `Api/Program.cs` before the first `/api/v1` endpoint; health endpoints intentionally keep their own JSON body.
- **Authz matrix (#26).** The OpenAPI document already contains the anonymous `System` endpoints (`/health/*`); the generator needs an explicit allow-list for anonymous operations rather than special-casing paths.
- **Job queue (#27).** `JobLoopService` + heartbeat + `job-loop` readiness check are the intended extension point; keep the heartbeat beating while idle-polling so long `SKIP LOCKED` waits don't turn the worker unready.
